# VoiceStage — дорожная карта

Pet-project: PWA для музыкальной студии (1 директор + 5 педагогов, ~30 детей,
индивидуальные и групповые занятия, несколько кабинетов).

**Формат работы:** один модуль = одна сессия (чат). В начале сессии Claude
читает этот файл и память, чтобы понять, где мы. В конце модуля — отмечает его
здесь как выполненный и фиксирует, что сделано.

Стек: React + TS + Vite (PWA) · Tailwind · Supabase (Postgres + Auth + RLS) ·
деплой на Vercel. Вход: Email OTP (код) через Resend SMTP или Google.

**Прод:** https://voice-studio-ruby.vercel.app — обновляется сам при каждом
пуше в `main` репозитория `Crystal-io/VoiceStudio` (подробности — в README).

## ✅ M0 — Фундамент (готово)
- Каркас проекта, PWA, Tailwind, клиент Supabase.
- Схема БД: студии, профили, кабинеты, ученики, группы, расписание, занятия,
  посещаемость (+ флаг оплаты `is_paid`, сумма `amount` скрыта).
- Вход без пароля (Email OTP) + доставка писем через Resend.
- Онбординг-механика: приглашения + триггер авто-привязки профиля при 1-м входе.
- Студия «VoiceStage» создана, `voicestage.io@gmail.com` — директор.

## ✅ M1 — Оболочка + Справочник «Педагоги и кабинеты» (директор) — готово

  защита директорских маршрутов, экран «доступ не открыт».

- Бонусом: кнопка входа «Продолжить с Google» (нужна разовая настройка

- **Итог:** директор наполняет студию людьми и кабинетами.

## ✅ M2 — Справочник «Ученики и группы» — готово
- Раздел «Ученики» в нижнем меню, внутри переключатель «Ученики | Группы»
  (одна вкладка вместо двух — меню не разрастается к M3).
- Ученики: список с возрастом и группами, поиск (когда учеников больше 6),
  карточка (имя, дата рождения → возраст, контакт родителя с кнопкой
  «Позвонить», заметки, группы — чипами), добавить, в архив / вернуть.
- Группы: создать, переименовать, состав галочками (с поиском), в архив /
  вернуть. Состав можно править и из карточки ученика.
- БД: у групп появилось `is_active` — группы не удаляются, а архивируются
  (удаление стёрло бы каскадом их занятия и посещаемость).
- Главная директора: счётчики учеников и групп.
- Заодно: в палитре не было `brand-950` — тёмная тема для иконок/аватарок
  не срабатывала (кабинеты, главная); системный выбор даты — в тон теме.
- **Итог:** есть кого и в каком составе записывать на занятия.

## ✅ M3 — Расписание — готово
- Раздел «Расписание» (у директора и у педагога): неделя с точками на днях,
  где есть занятия, режимы «День | Неделя», листание недель, «Сегодня».
  Директор видит всех (цвет полоски = педагог) и может отфильтровать одного;
  педагог — только свои занятия.
- Новое занятие: индивидуальное/групповое, разовое или «каждую неделю»
  (сразу несколько дней недели), дата начала и необязательная дата конца,
  время, длительность, кабинет, педагог. Педагог ставит занятия только себе.
- Занятие: перенести (только его), отменить/вернуть, удалить разовое,
  «Изменить расписание серии» — с выбранной даты (старая серия заканчивается
  накануне, прошлое не трогается), «Остановить повторение».
- Пересечения: перед сохранением проверяются педагог и кабинет по всем датам
  (для серии — на 16 недель вперёд); найденные показываются списком, можно
  поправить или «Сохранить всё равно».
- Главная: блок «Сегодня» — педагогу свои занятия, директору все.
- БД: `sessions.occurrence_date` + уникальность (серия, дата вхождения);
  функции `generate_series_sessions`, `ensure_sessions` (занятия создаются из
  серий заранее, на 16 недель вперёд, досоздаются при открытии расписания),
  `update_series`, `stop_series`, `schedule_conflicts`; триггер проверки, что
  педагог/кабинет/ученик/группа из той же студии; цвет педагога выдаётся
  базой автоматически (свой у каждого).
- **Итог:** расписание полностью ведётся в приложении.

## ✅ M4 — Посещаемость + флаг оплаты — готово
- В карточке занятия — список детей (ученик или состав группы + все, у кого
  уже есть отметка). Статус в одно касание: «Есть / Опоздание / Пропуск /
  Уважит.» (подписи без рода); повторное касание снимает отметку. Для групп —
  «Все пришли» / «Остальные пришли».
- Флаг «оплачено» у каждого ребёнка (сумма хранится, но скрыта). Оплату можно
  отметить заранее; посещение — только с дня занятия.
- Занятие само становится «проведено» после первой отметки (и возвращается в
  «запланировано», если отметки сняли); проведённое нельзя отменить.
- Карточки в списках: сводка «Опоздание · оплачено», «Были 4 из 5 · оплатили
  3»; прошедшие без отметок — метка «не отмечено».
- Главная: «Не отмечена посещаемость» — прошедшие занятия за 30 дней без
  отметок (первые 5); карточка занятия открывается прямо с главной.
- БД: `attendance.status` может быть пустым; триггеры — студия из занятия,
  кто и когда отметил, синхронизация статуса занятия.
- **Итог:** педагог отмечает посещаемость и факт оплаты.
